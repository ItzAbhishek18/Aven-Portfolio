PROJECT / 001

COLLEGE ASSIGNMENT · SOFTWARE SYSTEM

TAXI BOOKING SYSTEM.

A Python desktop application designed to simulate a taxi booking workflow through separate Customer, Driver, and Admin roles.

TECHNOLOGY Python / Tkinter
TYPE Desktop Application
CONTEXT College Assignment
STATUS Prototype / Completed
APPLICATION / LOGIN SCREEN
01 — OVERVIEW

A SMALL SYSTEM WITH MULTIPLE MOVING PARTS.

This project was developed as a college assignment to explore the design and implementation of a taxi booking system.

Instead of building separate programs for each type of user, the system combines Customer, Driver, and Admin roles into a single desktop application.

The different roles interact with the same ride information, creating a simple end-to-end booking workflow.

02 — SYSTEM

THREE ROLES. ONE SYSTEM.

01

CUSTOMER

Requests rides, selects a payment method, views ride status, cancels eligible rides, and can rate an assigned driver.

02

DRIVER

Views requested rides, accepts available rides, and updates the ride status as the trip progresses.

03

ADMIN

Manages users and rides from an administrative dashboard.

03 — WORKFLOW

FROM REQUEST TO COMPLETION.

01 REQUEST

Customer enters pickup and destination information.

→
02 ACCEPT

Driver sees the requested ride and accepts it.

→
03 PROGRESS

Driver changes the ride status as the trip progresses.

→
04 COMPLETE

Ride is marked as completed and becomes visible to the customer.

04 — THE CHALLENGE

MAKING THE PIECES WORK TOGETHER.

The hardest part of the project was combining the different user roles and making the system function as one application.

A customer, driver, and administrator all interact with different parts of the same ride data. Making those interactions work together required careful thinking about program logic and state changes.

05 — TECHNICAL APPROACH

PYTHON LOGIC AT THE CORE.

The application uses Python with Tkinter to create the desktop interface.

User roles are represented in the application and determine which dashboard is displayed after login.

Ride records contain information such as customer, pickup, destination, status, assigned driver, payment method, and creation time.

06 — WHAT I LEARNED

BUILDING IT CHANGED HOW I THINK.

The project helped me understand Python logic in a more practical way rather than only working with isolated exercises.

I also learned more about diagrams, mathematics, and how different parts of a software system need to connect and work together.

07 — CURRENT LIMITATIONS

A PROTOTYPE, NOT A PRODUCTION PLATFORM.

The current implementation uses in-memory data structures rather than persistent database storage.

Payment methods are represented as selections within the system rather than connected to real payment processing.

These limitations define the project as an academic prototype and also provide clear directions for a future version.
